# 관리자 운영 가이드

> 화면별 스크린샷과 감사/주의 배지가 포함된 **[인터랙티브 관리자 가이드](https://kovalt03.github.io/my-blog/guides/admin-guide.html)** 를 함께 제공한다(GitHub Pages 라이브 · 로컬에서는 [`docs/guides/admin-guide.html`](./admin-guide.html)). 이 문서는 운영 절차와 정책의 텍스트 기준이다.

관리자 화면은 `/admin/login`에서 별도 로그인한다. 관리자 권한과 TOTP 인증이 필요하며, 실제 운영·리허설은 [로컬 Docker 실행 환경](../operations/local-production.md)을 기준으로 한다.

## 최초 보안 설정

1. 운영 가이드의 `ADMIN_SEED_EMAIL`, `ADMIN_SEED_PASSWORD`로 최초 관리자만 만든다.
2. `/admin/login`에서 로그인하고 TOTP를 설정해 인증 앱의 코드를 사용한다.
3. 시드 환경 변수를 제거하고 재기동한다.
4. 외부 환경에서는 `ADMIN_IP_ALLOWLIST`를 반드시 설정한다.

관리자 비밀번호·TOTP 시크릿·JWT·DB 비밀번호는 채팅, 문서, Git에 기록하지 않는다.

## 화면별 기능

| 화면 | 경로 | 운영 내용 |
|---|---|---|
| 대시보드 | `/admin/dashboard` | 서비스·게임 운영 지표를 확인한다. |
| 영토 구성 | `/admin/continents` | 대륙별 영토 등급, 경매 공급·강제 시작을 관리한다. |
| 경매 관리 | `/admin/auctions` | 경매 상태를 조회하고 필요 시 정산·취소한다. |
| 시즌 운영 | `/admin/seasons` | 시즌과 시즌 패스 상태를 확인·조정한다. |
| 아이템·건물·유닛 | `/admin/items`, `/admin/buildings`, `/admin/units` | 게임 밸런스와 지급 기준을 관리한다. |
| 사용자 관리 | `/admin/users` | 계정 상태·자산·입찰·영토 이력을 확인하고 제한된 조치를 수행한다. |
| 채팅 검열 | `/admin/chat` | 신고 또는 운영상 문제가 있는 채팅을 검토한다. |
| 공지 배너 | `/admin/announcement` | 사용자에게 표시할 공지를 관리한다. |
| 감사 로그 | `/admin/audit-logs` | 관리자 변경 이력과 사유를 확인한다. |

## 권장 운영 순서

1. **대시보드 확인**: 장애·이상 징후와 현재 경매·시즌 상태를 먼저 확인한다.
2. **대상 조회**: 사용자·영토·경매를 변경하기 전 대상 ID, 현재 상태, 영향 범위를 확인한다.
3. **최소 변경**: 필요한 최소 대상부터 처리하고, 대량 변경은 사유와 범위를 다시 검토한다.
4. **결과 검증**: 변경 후 해당 화면과 감사 로그에서 결과를 확인한다.
5. **사고 대응 기록**: 변경 시각, 대상, 사유, 감사 로그 ID를 보존한다.

## 변경 전·후 체크

1. 사용자 재화·상태·경매·밸런스를 바꾸기 전 변경 사유를 남긴다.
2. 한 번에 넓은 범위를 바꾸기보다 소수 대상에서 결과를 확인한다.
3. 사용자 재화, 상태, 경매, 밸런스 변경 후 감사 로그를 확인한다.
4. 사고 대응이 필요하면 변경 시각과 감사 로그 ID를 보존하고, DB 복구는 [로컬 운영 실행 가이드](../operations/local-production.md)의 절차로 별도 수행한다.
